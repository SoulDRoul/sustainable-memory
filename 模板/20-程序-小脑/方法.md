# 方法与规则

三个文件管“记什么”。这一页管“怎么判断”：东西放哪、什么时候动手、规则怎么改、出错怎么归因。
每一节都可以单独用，不必全收。

## 一、分类四问

拿到任何文件或段落，按顺序问：

1. 它现在还成立吗？　不成立 → 归档
2. 它只对某一个项目成立吗？　是，未开工 → `30/<项目>/`；已开工 → `40/<项目>/`
3. 它是什么？　规则 / 结论 → `00`；时间与过程 → `10`；流程 / 步骤 → `20`；未验证的猜想 → `30`
4. 拿不准 → `99`，不要新建目录

00 和 10 最容易混，用一句分清：**能被修改的 → 00（它会变，所以要版本）；到死都不改的 → 10（它只记录发生过什么）。**

用不到的目录不要建。空目录是欠债。

## 二、动手前：三查

1. 规则查了吗？`00` 里有没有明确覆盖这个动作。
2. 有没有被否过？项目目录里的“已否定的方向”、否决清单。
3. 现在想干什么？推进项目 / 维护工作区 / 回答用户——三种意图的权限不一样。

三查降低漏查率，但它不消除判断。规则的解释仍要一次判断，承认这一点比假装它不存在好。

## 三、两条判断：值不值得 / 能不能做

**先问值不值得，再问能不能做；两关都过才动手。**

**前提：信息够不够。** 先问：要判断这件事，我还缺哪几件事？现在拿得到吗？
拿得到 → 先拿，再判断；拿不到 → 判断降级为“暂定”，并写明缺的是什么。
信息不足时，最好的方案也有上限，这个上限不能靠推理补——在信息缺口上盖一座逻辑完美的房子，是最贵的错。

- **比例（决定做多少）**：这件事的收益，配得上它的能耗吗？
  按请求类型定预算——问一句 → 只回答；小改 / 记一条 → 只动必要文件；
  审计 / 重构 / 不可逆 → 先说范围和预算。
- **可逆（决定能不能做）**：效果是不是全部落在版本控制管得到的范围内？
  是 → 直接做，事后说明；否 → 先问。

判据用“可逆”，不用“我有多确定”——确定性没有刻度，可逆性有上限。

**可逆 ≠ 无害。** revert 救不回来的东西，一律不可逆：花掉的时间、工作区外的副作用、写进 git 历史的密钥、信任损耗。

**说明必须具体。** “已完成”不算说明。写清删了什么、改了什么、涉及哪些文件、怎么退回。
做工程 / 写代码时，“好了 / 通过了”必须附命令、输出、日期；没有证据就写“还没验证”。
这条是“直接做”的对价：要求少问，就得接受多解释。

## 四、规则的规则

1. 加一条，删一条。找不到能删或合并的旧规则，说明新规则还不够重要。
2. 每条规则必须能用“是 / 否”检验，而且判定不需要额外劳动。
   需要查表、统计、回忆才能判断的规则，等于不可判定。
3. 规则文件有行数上限（比如 250 行）。超了先删，再考虑加。
4. 同一件事只能有一份程序。两套并存的规则，结果等于没有规则。
5. 规则由摩擦驱动，不由设计驱动——只有真用起来，摩擦才会出现。

## 五、规则演化：为什么改

单独一份 `规则演化.txt`，只记“如果忘了理由就会改回去”的规则。

格式固定四行：

    规则：改成什么
    原来：之前是什么
    为什么改：触发它的那次摩擦
    改回去会怎样：写不出后果的，说明它根本不值得记

最后一行是筛子。改规则之前，先读这里对应的一条；读完还觉得该改，再改。

## 六、出错之后：归因四问

出了错，先别改规则，按顺序问：

1. 当时查了吗？　没查 → 流程问题（改清单，不改规则）
2. 查了，规则覆盖这件事吗？　没覆盖 → 缺口（加规则，但按“一进一出”付账）
3. 覆盖了，按规则做了吗？　没做 → 执行问题（规则太隐蔽，挪到看得见的地方）
4. 做了还是错 → 规则本身错（改规则，并写明“改回去会怎样”）

最常见的误判：把“没执行”当成“规则错”，然后规则越写越多，错误不见减少。

**归因靠轨迹，不靠回忆。** 事后回忆会自动合理化——所有人事后都觉得自己当时查过。
所以做判断时就在回复里留痕：查了哪几处、可逆性依据是什么、因此直接做了什么。
没有轨迹，归因等于编故事。

## 七、文件长什么样

页眉：每个文件第一行。

    [类别: 语义] [文件: 当前状态] [状态: 当前] [更新: 2026-01-01]

- 状态四种：当前 / 参考 / 过期 / 草稿。
- 只写类别和文件名，不写路径——这样改目录名，文件里的引用不断（脚本仍按路径找文件，改目录要同步改脚本）。
- 交接笔记多一行：`[上一份: 2026-01-01-上一份.txt]`，没有就写“无”。
- 页眉不超过三行：脚本只读前三行来找“上一份”，写长了会找不到。

命名：

- `10-情景`：日期打头，天然按时间排。
- `00` / `20`：不带日期（不是某天发生的事）。
- `30`：带日期（想法本身有时间价值）。
- 避开空格、全角标点、《》——它们在命令里要转义。

记忆链：顺着“上一份”往回走，能找到更早的每一份。要判断“哪份最新”，反过来看：
没被任何笔记写成“上一份”的那份，就是链尾。两条一起用，才既不漏也不猜。
断了一天写“无”即可；链不必完美，能用就行。

生长与衰退：

- 同一目录里出现第三类明显不同用途的文件，才分裂新目录。
- 连续三个月没有新文件，合并回上级，或归档。
- 空目录是欠债，不要为想象中未来的项目预建。

## 八、备份

- git 管“改坏了能退回”：提交要密，大改之前单独存一次。
- 离线副本管“电脑没了还有一份”：每月一次，另一块硬盘。
- 两者不能互相替代：同步会把坏版本一起带过去，副本没有历史。
- 同步盘不算备份；备份要能“退回”，不只是“复制”。
- 每半年做一次恢复演练——这是唯一真正的验证。
- `99-临时` 不备份，那里只放随时可清空的东西。

## 九、环境自检（第一次开工前，只做一次）

同一套文件，换台电脑、换个 agent、换个模型，能做和不能做的事不一样。
先分三档，再决定怎么走——不要把“缺东西”当成“做不了”。

**挡路的（解决不了就别开始）**

- agent 读不了或写不了文件。这套方法的地基是文件，这一条没有替代方案。

**能让路的（降级也能走，但要说清代价）**

- 没有 Python：不跑脚本。链尾、覆盖至、提交都手写；脚本只是省手，不是规则。
- 没有 git：不提交，就没有“退回”。每次收尾前手动复制一份。
- 没有 shell：只能读写文件，上面的两条都按“没有”处理。

**要留意的（不挡路，但会变味）**

- 装过记忆类、上下文类插件：可能多出一个记忆源。先提交，再观察一轮；
  文件被改了、否决被淡化了，就停、报冲突，不要替它合并。
- 换了模型：先跑一次回忆。对不上就改文件，不假设“它还认得”。

自检清单（只读，一屏内）：

    1. 能不能列出 `10-情景-海马/`？
    2. 能不能读 `当前状态.txt` 的第一行？
    3. 能不能在 `99-临时-间隙/` 写个测试文件，再删掉？
    4. `python --version` 或 `python3 --version`（有就记版本）
    5. `git --version`（有就记版本）

结果只有三种：全过 → 正常走；缺 4 或 5 → 降级，并告诉用户失去什么；
缺 1–3 → 停，说明这套方法在这里用不了。

出错时的三条（不猜、不装、不合并）：

- **命令不存在** → 说“缺 X”，换替代路径；不假装跑过。
- **文件读不到** → 说缺哪份，不用推测补。
- **记忆和预期不一致**（被插件改、被压缩、乱码）→ 停，先看 `git status` 或备份，
  再问用户；不要自行“修好”。

## 十、谁写记忆

这一条是方法的分工，不是可选的便利。

- 笔记由 AI 写，人负责判据与否决。它写、它改、它起草；你定方向、能不能过。
- 人可以读、可以要求改、可以直接改；但**改之前先读**。乱改最大的危害不是改错，
  是改的人不知道自己改了什么。
- 写进去的必须是判断（同意什么、反对什么、为什么），不是摘要。
  摘要进来，记忆就退化成检索了。
- 一次没写对的不用删掉重来：加一行“修正自某条”，保留原来怎么想、为什么改。
  最终结论谁都记得住，改的路径才是资产。

## 十一、三条判据

决定“记什么、怎么记”，用这三条：

1. **接续优先于保真。** 判据不是“像不像上次那个人”，是“下一步接不接得上”。
   保真度有最优区间：太低接不上，太高读不完。
2. **否决优先于正面清单。** 位置由排除定义。所以“不要什么”比“要什么”更硬、更省、
   更不容易膨胀——正面条目天生容易变成愿望列表。
3. **可判定的写成脚本，判断留在表面。** 一条规则如果经常需要解释，它就不是规程，是判断；
   硬写成规程，就会出现“照做但结果不对”。

## 十二、一起读点什么

这一节不是教你把资料塞进去——塞进去的只会是摘要。
决定这套东西长成什么的，不是读了多少，是怎么读。

1. **一次一段。** 整本塞进去，出来的必然是摘要；摘要连二手综述都算不上，出处早被压掉了。
2. **让它先下判断，你再核对；它也核对你的回答。** 不必谁说服谁——不一致的地方记下来，
   不必当场解决。能进记忆的不是共识，是分歧；共识只是回声。
3. **只记判断，不记内容。** 记“我为什么反对这句”，不记“这本书讲了什么”。
4. **一个库一个人。** 画像和否决都长在一个人身上。多人共用一个库，得到的不是更丰富的记忆，
   是没有立场的记忆。
5. **读什么不重要。** 重要的是你不同意了什么。读经典和读网文，留下的可以是同一种形状。

一句失败判据，让人自己能看出来：

> 一个月后，如果文件里全是摘要和感想，没有一条带出处的判断，那这套东西已经退化成检索了。

一句前提，不太好听，但该写：

> 它放大使用者，不制造使用者。本身没有判断的人用它，会把 AI 的偏见固化成“我的立场”，
> 而且有文件为证，更难改。
